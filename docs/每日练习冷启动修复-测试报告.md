### E16 复现步骤

```bash
# 1) 克隆库起服务
DB_NAME=online_exam_qa ./.venv/Scripts/python.exe manage.py runserver 127.0.0.1:8011 --noreload
# 2) 以 student / Exam@123456 登录后访问
http://127.0.0.1:8011/practice/?subject=操作系统
# 3) 观察：下拉框只有「全部学科 / 数据结构」，页面是数据结构的 normal 推荐
```

### 根因（页面层，与 `services.py` 无关）

- `templates/recommend/practice.html:754` 立即执行 `load(true)`，而 `load()` 使用的是 `currentSubject()`＝下拉框当前值。此时 `<select id="subject-select">` 里只有「全部学科」（`practice.html:80-82`），`INITIAL_SUBJECT` 还没被写进去，于是首个请求的 subject 恒为 `""`。
- `INITIAL_SUBJECT` 只在 `renderSubjects()`（`practice.html:181`）里用于「回填选中项」，但选项来自接口的 `data.subjects`，而 `RecommendationService.subjects()`（`services.py:896-905`）只返回**该学生有已判分作答的学科**。`student` 只有数据结构作答 → 选项里没有操作系统 → 回填失败，`value` 保持 `""`。
- 因此，即使手工在 URL 上带 `?subject=操作系统` 也无效；下拉框也没有任何路径能选到三个新学科。后端 `GET /api/v1/recommend/students/3/practice/?subject=操作系统` 直接调用是本报告 A1 的 PASS 结果。

**修复建议（未实施，供实现者参考）**：首屏 `load()` 显式传 `INITIAL_SUBJECT`（或先把 `select.value` 设为 `INITIAL_SUBJECT` 并补一个同名 option）；同时让学科下拉包含「有启用题的学科」，否则新学科在页面上永远不可选。

## 风险 / 限制（非阻断）

1. **starter 提示条含「薄弱」字样**：`practice.html:430` 固定文案「做完这组会开始按薄弱知识点推荐。」导致 E16 / E18 的「页面无『薄弱』字样」不成立。语义没错（说的是后续行为），但与验收口径字面冲突；`check_practice_js.py` 只校验 KPI / 页脚，覆盖不到这行。
2. **候选池偏小**：三学科均为 7 个知识点 × 2 = 14 道（`_starter_rows` 不留溢出区），`size=20` 也只能拿到 14 道；「换一批」第二页即到末尾。当前可接受，但如果希望入门练习能连续做几天，需要重新评估「每知识点 2 道 + 无溢出」。
3. **starter 下 KPI「已判分题数 = 0」**：统计的是该学科口径，数值真实，但与「入门练习」并列时容易被学生误读为「系统没读到我的数据」。属文案层面。
4. **一个知识点多挂载**：题库中 1 道题同时挂「TCP 协议 / UDP 协议」，starter 只按 `next(iter(knowledge_points.all()))` 取第一个（实测稳定为 TCP），UDP 不参与限流统计。当前数据量下无影响，且 8 次重复调用顺序稳定。
5. **C11 的排除逻辑在真实流程中不可达**（该学科一旦有正确作答就走 normal），只能以「卷面学科 ≠ 题目学科」构造验证；属防御性代码，不是缺陷。
6. **无 Git 仓库**：A2「与修复前一致」无法做差分对比，只能用旧文案、旧公式、独立重算三路交叉验证；F22 也无法做逐行 diff。
