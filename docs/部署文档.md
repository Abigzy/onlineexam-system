# 部署文档 · AI 在线考试与学情分析系统

> 适用版本：Django 4.2 + DRF，Python 3.11+
> 本文所有命令与输出均在本机实测过（Windows 10 + MySQL 5.6.46），Linux 生产命令已标注区别。

---

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Python | 3.11 ~ 3.13 | 实测 3.13 |
| 数据库 | MySQL 8.0+（推荐） / MySQL 5.6（兼容） | 5.6 已于 2018 年停止维护，正式交付建议升 8.0 |
| 内存 | ≥ 2 GB | 含 scikit-learn（孤立森林）时建议 4 GB |
| 操作系统 | Linux（生产） / Windows（开发、演示） | gunicorn 不支持 Windows，见第六节 |

**关于 MySQL 5.6**：Django 4.2 官方要求 8.0.11+。用 5.6 时必须保留 `.env` 里两行兼容配置：
- `DB_SKIP_VERSION_CHECK=True`（跳过版本校验）
- `DB_CHARSET=utf8`（5.6 的 InnoDB 单列索引上限 767 字节，`utf8mb4` 建表会失败）

升到 MySQL 8.0 后这两行可以删掉，并改用 `utf8mb4`。

## 三、数据库

### 3.1 创建库与账号

MySQL 8.0（推荐）：

```sql
CREATE DATABASE online_exam
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'exam'@'localhost' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON online_exam.* TO 'exam'@'localhost';
FLUSH PRIVILEGES;
```

MySQL 5.6（兼容模式）：

```sql
CREATE DATABASE online_exam CHARACTER SET utf8 COLLATE utf8_general_ci;
```

> 字符集必须显式指定。不指定时继承服务器默认（常见为 latin1），中文写入会报 `1366 Incorrect string value`。

### 3.2 时区

应用侧已用 `DJANGO_TIME_ZONE=Asia/Shanghai`；数据库建议 `default-time-zone = '+08:00'`，避免 `USE_TZ` 与数据库时区叠加造成 8 小时偏差。

## 四、`.env` 配置

复制模板：

```bash
cp .env.example .env
```

### 4.1 生产环境必须改的项

| 变量 | 生产取值 | 说明 |
|---|---|---|
| `DJANGO_SETTINGS_MODULE` | `OnlineExam.settings.production` | 开发用 `development` |
| `DJANGO_SECRET_KEY` | 重新生成（≥ 50 字符） | **不要用模板里的 dev key** |
| `DJANGO_DEBUG` | `False` | 生产必须 False |
| `DJANGO_ALLOWED_HOSTS` | `exam.example.com` | 逗号分隔，**不能为空**，否则所有请求 400 |
| `DB_ENGINE` | `mysql` | 默认 `sqlite` 仅用于快速试跑 |
| `DB_NAME/DB_USER/DB_PASSWORD/DB_HOST/DB_PORT` | 实际库信息 | — |
| `SECURE_SSL_REDIRECT` | `True` | 无 HTTPS 的本机演练可临时设 `False`，否则 curl 会一直吃 301 |
| `CSRF_TRUSTED_ORIGINS` | `https://exam.example.com` | 后台与表单提交必需，否则 CSRF 校验失败 |
| `CORS_ALLOW_ALL_ORIGINS` | `False` | 生产关闭通配 |
| `AI_ALLOW_MOCK` | `False` | 正式环境不要让大模型静默降级成假回答 |

### 4.2 生产路径（`production.py` 才生效）

| 变量 | 默认值 | 建议 |
|---|---|---|
| `DJANGO_LOG_DIR` | `<项目根>/logs` | `/var/log/onlineexam`（需可写） |
| `DJANGO_STATIC_ROOT` | `<项目根>/staticfiles` | `/var/www/onlineexam/static` |
| `REDIS_URL` | 空（用本地内存缓存） | `redis://127.0.0.1:6379/1`，多 worker 时必须配 |

### 4.3 AI 配置

`AI_PROVIDER` 可选 `deepseek` / `doubao` / `yuanbao` / `openai`，各自的 `*_API_KEY` 与 `*_BASE_URL` 填对应值。

> **注意**：`AI_REPORT_TTL_HOURS` 是代码常量（`apps/analytics/constants.py`），**不是环境变量**，写进 `.env` 无效。

未配 Key 时系统会自动降级为 mock（`AI_ALLOW_MOCK=True` 时），功能不中断但内容是模拟的——这是预期行为，不是故障。

### 已有部署的升级

代码更新后**必须先跑迁移再重启服务**，顺序不能反：

```bash
git pull
python manage.py migrate                    # 应用增量迁移
python manage.py collectstatic --noinput    # 前端资源有变动时
# 然后重启 gunicorn
```

> 本次交付相对上一版新增 `papers.0002_alter_paper_generation_mode`
> （`generation_mode` 增加 `random` 取值，支撑「随机组卷」）。
> 它**只改字段的 choices 元数据，不改列结构、不动数据**，执行是秒级；
> 但漏执行会让 `showmigrations` 留下 `[ ]` 未应用项——上线核对时会被判为「迁移没跑完」，
> 而且新功能虽然能跑、状态却与代码不一致。

## 六、静态文件

```bash
python manage.py collectstatic --noinput
```

### 6.1 这一步不能省

实测：**漏掉 `collectstatic` 不是"样式丢失"，而是页面直接 500**：

```
ValueError: Missing staticfiles manifest entry for 'css/style.css'
```

生产用 `ManifestStaticFilesStorage`，模板渲染时按 manifest 查带哈希的文件名，查不到就抛异常，整个页面打不开。

### 6.2 实测结果

```
164 static files copied to '/var/www/onlineexam/static', 164 post-processed.
```

目录内共 329 个文件 = 164 原始 + 164 带哈希副本 + `staticfiles.json`。

### 6.3 `runserver --insecure` 也服务不了生产静态文件

`collectstatic` 产出的是 `css/style.8bbc6fa80bd0.css`，而 `--insecure` 只从 `STATICFILES_DIRS` 找原始文件，找不到哈希产物 → 404。

**生产必须由 Nginx `alias` 到 `STATIC_ROOT`**，不能靠 Django 服务静态文件。

## 七、应用服务器

### 7.1 Linux（gunicorn）

```bash
pip install gunicorn

gunicorn OnlineExam.wsgi:application \
  --bind 127.0.0.1:8000 \
  --workers 3 \
  --threads 2 \
  --timeout 60 \
  --access-logfile - \
  --error-logfile -
```

`--workers` 经验值 `2 × CPU核数 + 1`；`--timeout 60` 要给 AI 批改留余量（单题批改可能十几秒）。

systemd unit 示例：

```ini
[Unit]
Description=OnlineExam
After=network.target mysql.service

[Service]
User=www-data
WorkingDirectory=/opt/onlineexam
EnvironmentFile=/opt/onlineexam/.env
ExecStart=/opt/onlineexam/.venv/bin/gunicorn OnlineExam.wsgi:application \
    --bind 127.0.0.1:8000 --workers 3 --threads 2 --timeout 60
Restart=always

[Install]
WantedBy=multi-user.target
```

### 7.2 Windows（开发/演示）

**gunicorn 在 Windows 上不可用**：能装上（26.2.0），但启动即 `ModuleNotFoundError: No module named 'fcntl'`（gunicorn 依赖 Unix 的 `fcntl`）。

替代方案：
- 演示用：`python manage.py runserver 0.0.0.0:8000`（`DEBUG=False` 时静态文件需 `--insecure`）
- 生产用：`waitress-serve --listen=0.0.0.0:8000 OnlineExam.wsgi:application`

## 八、Nginx

```nginx
server {
    listen 80;
    server_name exam.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name exam.example.com;

    ssl_certificate     /etc/ssl/certs/exam.crt;
    ssl_certificate_key /etc/ssl/private/exam.key;

    client_max_body_size 20m;          # 题库 Excel 导入、头像上传

    location /static/ {
        alias /var/www/onlineexam/static/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location /media/ {
        alias /var/www/onlineexam/media/;
    }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # 这一行必须有：production.py 的 SECURE_PROXY_SSL_HEADER 靠它判断 https
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 90s;        # AI 批改留余量
    }

    gzip on;
    gzip_types text/css application/javascript application/json;
}
```

### 8.1 缺 `X-Forwarded-Proto` 会无限 301

`production.py` 默认 `SECURE_SSL_REDIRECT=True`。Nginx 只反代 http 时 Django 看不到 https，会把每个请求再 301 到 https，形成 `ERR_TOO_MANY_REDIRECTS`。

实测对比：

```
GET http://127.0.0.1:8022/login/                          -> 301 https://...
GET http://127.0.0.1:8022/login/  (X-Forwarded-Proto: https)  -> 200
```

## 十、常见问题

### 1. 启动即崩：`ValueError: Unable to configure handler 'file'`

原因：日志目录不存在。`RotatingFileHandler` 在 Django 启动阶段就要求目标目录存在。

已修复：`production.py` 会主动 `LOG_DIR.mkdir(parents=True, exist_ok=True)`，目录可用 `DJANGO_LOG_DIR` 指定。若仍报错，检查该目录的写权限。

### 2. 页面 500：`Missing staticfiles manifest entry`

原因：没跑 `collectstatic`。见第六节。

### 3. 所有请求 400：`DisallowedHost`

原因：`DJANGO_ALLOWED_HOSTS` 没包含当前域名。实测伪造 Host 会返回 400，这是正确行为。

### 4. `ERR_TOO_MANY_REDIRECTS`

原因：Nginx 没传 `X-Forwarded-Proto`，或本机无 HTTPS 却开了 `SECURE_SSL_REDIRECT`。见 8.1。

### 5. 中文写入报 `1366 Incorrect string value`

原因：库/表字符集不是 utf8 系。检查 `SHOW CREATE DATABASE`，5.6 用 `utf8`，8.0 用 `utf8mb4`。

### 6. CSS 404，但文件明明存在

原因：浏览器请求的是 `style.<hash>.css`，Nginx 指向的却是开发目录。确认 `alias` 指向 `STATIC_ROOT`（collectstatic 的输出目录），而不是项目的 `static/`。

### 7. AI 功能返回的是模板化假答案

原因：`AI_ALLOW_MOCK=True` 且没配 Key，系统自动降级 mock。这是设计行为（保证课堂演示不因无网中断）；生产请配 Key 并设 `AI_ALLOW_MOCK=False`。
