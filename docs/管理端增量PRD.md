## 1. 问题陈述

### 1.1 一句话

`IsTeacher` 把管理员当成教师（`role in (TEACHER, ADMIN)`），导致**管理员在界面上就是"多了一个后台入口的教师"**——真正属于管理员的职能（账号治理）没有界面，而教师的教学职能却以最显眼的方式占满了管理员的视线，于是"越权"既不体现在拦截上、也不体现在提示上，完全隐身。

### 1.2 现状事实（代码定位，非推测）

| 编号 | 事实 | 位置 |
|---|---|---|
| F-1 | `IsTeacher` 判定为 `is_superuser or role in (TEACHER, ADMIN)`，注释直言"管理员天然拥有全部权限" | `apps/common/permissions.py:23-34` |
| F-2 | 模型属性 `User.is_teacher` 对管理员返回 `True` | `apps/users/models.py:78-80` |

### 1.3 "重合"到底带来什么损失

| # | 问题 | 具体后果 | 严重度 |
|---|---|---|---|
| P-1 | **该干的事找不到** | 管理员登录后第一屏是题库/组卷/学情，想停用一个离职教师账号，需要手动敲 `/admin/users/user/` 走 Django 原生后台（英文混排、无统一响应体、不遵循学科隔离），与他正在看的系统不像同一套产品 | 高 |
| P-2 | **误操作风险** | 管理员与教师共用同一套按钮和同一份数据，重置密码、停用等**危险操作没有界面**，反而"删除题库""归档考试"这类影响教学资产的操作在界面上一键可达且无差别提示 | 高 |
| P-3 | **权限越界不可见** | 管理员点进"作弊检测"和教师看到的是同一个页面，**没有任何"你正在以管理员身份操作他人教学数据"的提示**。出了问题无法从界面上回溯是谁动的手 | 高 |
| P-4 | **审计缺失** | 无登录日志表、无操作日志表；`record_login` 只更新 `last_login_ip` 一个字段；重置了谁的密码、停用了谁，事后查不到 | 中 |
| P-5 | **账号治理被绕过** | 公开注册允许自选"教师"角色（F-10）——用户管理页做得再好，也没人必须走它。管理员对"谁有教师权限"这件事实际上不掌握 | 高 |

### 1.4 本次明确不做（范围外）

- 不重做教师端与学生端的任何业务逻辑与视觉。
- 不引入 RBAC 权限框架（Django Guardian 之类），角色仍为三值枚举。
- 不做多租户 / 多学校隔离（`school` 字段仍只作展示与筛选）。
- 不改 Google/Django 后台 `/admin/` 的存在（它作为应急兜底保留，只是不再是管理员的日常入口）。

## 2. 角色权限矩阵

### 2.1 关键设计问题

> 管理员还要不要能进教师业务？

| | 方案 A：硬隔离 | 方案 B：软收口 |
|---|---|---|
| 定义 | 管理员**不能**进入任何教师业务页面，接口层对 admin 的教师业务请求只读或直接 403 | 管理员**保留**教师业务能力（超级权限），但默认导航与首页收敛为管理控制台，教师业务折叠进「教学管理（代管）」分组 |
| 优点 | 权限模型最干净，答辩讲"角色分离"最有说服力 | 不破坏任何既有行为；教师账号不可用时管理员能兜底；演示只需一个库 |
| 代价 | 需逐条改 `IsTeacher` 并**连带修改大量现有测试夹具**（现有 781 个测试里相当一部分用 admin 身份调教师接口），回归面不可控；教师账号一旦不可用，系统无人可维护 | 接口层"管理员仍能写教师数据"这一事实没变，需要额外的可见化手段回答"越权怎么办" |
| 对用户诉求的回应 | 完全满足 | 满足（用户抱怨的是"功能模块重合"，即界面与默认体验） |

### 2.2 推荐方案：**B+（软收口 + 代管留痕）**

即**方案 B 的收敛形态**，并补两条护栏：

1. **界面层严格分流**（P0）：导航、首页、默认落地页按角色彻底分开。管理员登录看不到题库/组卷/学情；要看，必须展开「教学管理（代管）」并接受界面提示。
2. **代管行为可见**（P0 界面提示 + P1 落库留痕）：以管理员身份进入任一教师页面时，页面顶部常驻一条提示条——「你正在以管理员身份代管教学功能，本次操作将按管理员身份记录」；P1 增加操作日志后，代管写入行为落 `OperationLog`。
3. **接口层本期不动** `IsTeacher` 的判定（保 781 测试零回归），但在权限矩阵里**显式承认**这一点，并把它列为 P2 的可选收紧项。

**推荐理由**

- **不破坏既有交付**：`IsTeacher` 一处判定被 781 个测试依赖，改它的收益是"模型更纯"，成本是回归面不可控 + 可能被迫改测试断言（违背"既有测试必须继续通过"）。
- **答辩现场更稳**：毕设演示通常一个数据库、两个账号。B+ 可以在同一个浏览器里**左右对比两个界面**——管理员登录看到管理控制台，教师登录看到教学台，这是"角色分离"这个设计点最直观的证据；方案 A 下如果现场只有 admin 账号，教师端根本演示不了。
- **符合真实系统的做法**：绝大多数教务系统里，管理员确实有"代管/兜底"能力（教师离职交接、数据修正），硬隔离会逼出"多人共用教师账号"这种更坏的实践，反而彻底破坏审计。
- **风险已用护栏对冲**：越权的核心危害不是"能点"，而是"点了没人知道"。B+ 用提示条 + 留痕把这个洞补上，比"禁止点击"更接近问题本质。

> 若评审要求硬隔离，方案 A 的落地清单见 §5 P2-1（本期不做，仅登记成本）。

### 3.4 数据总览指标定义（`GET /api/v1/system/overview/`）

| 分组 | 指标 | 口径 | 数据源 |
|---|---|---|---|
| 用户 | 总用户 / 各角色数 | `count` by `role` | `users` |
| 用户 | 停用账号数 | `is_active=False` | `users` |
| 用户 | 近 7 日新增 | `date_joined >= now-7d` | `users` |
| 用户 | 近 7 日活跃（登录过） | `last_login >= now-7d` | `users` |
| 组织 | 班级总数（行政班 / 学科班） | count by `class_type` | `classroom` |
| 组织 | 未绑定学科的教师数 | `role=teacher AND subject=""` | `users` |
| 内容 | 题库题量（按题型 / 按启用状态） | count 聚合 | `questions` |
| 内容 | 试卷数 | count | `papers` |
| 教学 | 考试数（按 `ExamStatus`） | count 聚合 | `exam` |
| 教学 | 近 7 日参考人次 / 已出分人次 | `ExamAttempt` count | `exam` |
| AI | 近 7 日调用次数 / 失败率 / token 总量 / 是否 mock | `AIRequestLog` 聚合 | `ai` |
| 候选项 | 库内已有学科值去重列表 | `distinct subject` | `users` + `classroom` |

> AI 用量放在管理端首页，是因为它是**系统级成本**，教师看不到也没必要看；答辩时这一块能直接回答"AI 到底被调用了多少次、花了多少 token"。
> 全部指标单请求返回；查询全部走 `aggregate`，页面响应目标 < 300ms（万级数据量下）。

## 4. 用户管理页详细需求（P0 核心）

### 4.1 列表页

**列定义**

| 列 | 内容 | 备注 |
|---|---|---|
| 用户名 | `username`，等宽字体 | 越小屏越靠前 |
| 姓名 | `real_name`，空则显示 `—` | |
| 角色 | Badge（管理员/教师/学生） | 复用现有 `role-badge role-{{ role }}` 样式 |

| 邮箱 | `email` | 小屏隐藏 |
| 状态 | 启用 / 已停用（停用整行置灰） | |
| 最后登录 | `last_login`（相对时间，hover 显示绝对时间）+ `last_login_ip` | 空显示"从未登录" |

**列表行为**

- 分页：`page` / `page_size`（默认 10，可选 20/50/100，上限沿用后端 `max_page_size=100`），底部显示"共 N 条"。

- 每页条数、筛选条件可写入 URL query，便于刷新与分享。

**搜索与筛选**

| 控件 | 参数 | 说明 |
|---|---|---|
| 关键词搜索框 | `search=` | 匹配用户名 / 姓名 / 邮箱 / 学号 / 手机号（沿用后端 `search_fields`），回车或停顿 400ms 触发 |

| 注册时间 | `created_after=` / `created_before=` | 日期区间 |
| 清空筛选 | — | 一键复位并清空 URL query |

| 字段 | 必填 | 校验规则 | 控件 |
|---|---|---|---|
| 用户名 | 是 | ≥3 位；字母/数字/下划线；全局唯一（忽略大小写） | 文本框 |
| 邮箱 | 是 | 邮箱格式；全局唯一 | 文本框 |
| 真实姓名 | 否 | ≤32 字 | 文本框 |
| 角色 | 是 | 三选一，默认学生；选"管理员"时弹二次确认 | 单选/下拉 |
| 学号 / 工号 | 否 | ≤32 字；**可留空**——教师自动派工号、学生按年级派学号；手填则须与所选年级一致；同角色内唯一 | 文本框 |
| 入学年级 | **学生必填** | 4 位年份（当前年往前 3 年，如 `2026`）；用于派发学号；手填学号时校验前 4 位与之一致 | 下拉 |

### 4.3 编辑用户

- 可改：邮箱、姓名、角色、学号/工号、学科、手机号、学校。
- **不可改**：用户名（后端 `AdminUserSerializer` 已设为只读，界面按只读文本展示并附注"用户名创建后不可修改"）、注册时间。
- **状态不在编辑表单里改**：只能通过行内「停用/启用」明确操作，避免"改个手机号顺手把人停用了"。
- 后端既有护栏必须保留并在界面上前置提示：超级管理员角色不可降级（`validate_role`）。
- 新增护栏：不允许把**最后一个启用状态的管理员**改为其他角色或停用（否则系统失去管理员）。

### 4.4 行内操作与危险操作二次确认

| 操作 | 危险级 | 二次确认形态 | 说明文案要点 |
|---|---|---|---|
| 编辑 | 无 | — | — |
| 重置密码 | 中 | 模态框，需选择"随机生成"或"手动输入" | 说明"重置后该用户所有已登录会话立即失效，需用新密码重新登录" |
| 停用 | 中 | 模态框，列出该用户将被影响的能力 | "该账号将立即无法登录，其已有数据（题库、试卷、成绩）保留不变" |
| 启用 | 无 | — | 直接生效 |
| 删除 | 高 | **本期不提供**（见 §4.7） | — |
| 改角色 | 中 | 模态框，显示"从 X 变更为 Y"及影响范围 | 改为管理员额外强调"将获得系统全部管理权限" |

**通用规则**
- 所有危险操作使用 **POST**，带 CSRF token，不用 GET 触发。
- 对自己的账号：「停用」与「重置密码」按钮**禁用**并提示"不能对自己执行该操作，请到个人中心修改密码"（后端已有 `10007`/`10010` 拦截，前端前置避免无效点击）。
- 成功后局部刷新该行（或整页刷新，实现取简），并 Toast 提示。

### 4.5 重置密码规则

**密码来源（二选一）**
1. **系统随机生成（默认）**：12 位，大小写字母 + 数字组合，剔除易混淆字符（`0 O 1 l I`），使用密码学安全随机源。
2. **管理员手动输入**：需输入两次一致。

**强度校验（两种来源都必须通过）**——严格对齐 `AUTH_PASSWORD_VALIDATORS` 现有四项：

| 校验器 | 规则 | 失败提示 |
|---|---|---|
| `UserAttributeSimilarityValidator` | 与用户名、邮箱、真实姓名相似度过高 → 拒绝 | 密码与账号信息过于相似 |
| `MinimumLengthValidator`（`min_length=6`） | < 6 位 → 拒绝 | 密码长度不能少于 6 位 |
| `CommonPasswordValidator` | 命中常见弱口令字典 → 拒绝 | 该密码过于常见，请更换 |
| `NumericPasswordValidator` | 纯数字 → 拒绝 | 密码不能全部为数字 |

> **必须修复的现存缺陷（D-3）**：现有 `reset-password` 默认值为 `"123456"`，该值同时违反 `NumericPasswordValidator` 与 `CommonPasswordValidator`；且接口只校验 `len >= 6`，从未调用 `validate_password`。也就是说**系统自己生成的默认密码不符合系统自己的密码策略**，这是一处自相矛盾的口径，本期必须消除。

**结果交付**
- 新密码明文**仅在重置成功的响应中返回一次**，界面用模态框展示 + 「复制」按钮，关闭后不再展示。
- 不写入任何日志、不写入任何持久化字段、不在列表页回显。
- 重置成功后：该用户全部 refresh token 拉黑（沿用 `UserService.change_password` 的既有口径），页面会话立即失效。

### 4.6 启用 / 停用与登录行为

| 场景 | 现状 | 本期目标 |
|---|---|---|
| 停用后 API 鉴权 | SimpleJWT 校验 `is_active`，下一次请求即 401 ✅ | 保持 |
| 停用后**已登录的页面会话** | Django 默认**不校验** `is_active`，已登录用户可继续点页面 ⚠️ | 增加轻量校验：命中停用则强制登出并提示"账号已被停用，请联系管理员" |
| 停用后页面登录提示 | 实际提示"账号或密码错误"（"已停用"分支不可达，见 F-9） | 仅在「账号存在 **且** 密码正确」时提示"该账号已被停用，请联系管理员"；否则仍统一"账号或密码错误"，**不得**引入账号枚举风险 |
| 停用后 JWT 登录提示 | "No active account found with the given credentials" | 与页面口径一致（P1 可选） |
| 停用范围 | — | 不允许停用自己；不允许停用最后一个启用管理员 |

### 4.7 删除策略（明确建议：本期不做物理删除）

**事实依据**
- `ExamAttempt.student` 是 `CASCADE`：删一个学生会**连带删除该生全部作答记录与成绩**，成绩单与学情分析出现不可恢复的空洞。
- `created_by` 系列是 `SET_NULL`：删一个教师会让题库、试卷、考试、班级的"创建人"变成空，历史归属永久丢失。

**结论**
- 管理端界面**不提供删除入口**，用「停用」替代（可逆、保留全部关联数据）。
- 后端 `DELETE /api/v1/users/{id}/` 接口**保留不动**（避免影响既有测试与其他调用方），只是管理端不调用它。
- 若确有"彻底清除"需求，走 P1-3「归档」：停用 + 释放唯一键占用（用户名/邮箱/学号打标记），仍保留成绩关联。此方案需评审确认。

| 用途 | 接口 | 结论 |

### 4.10 关联整治：注册入口（P0，1 行判断）

**问题**：公开注册页允许自选 `teacher` 角色（F-10）。这意味着管理员精心设计的"用户管理"可以被完全绕过——任何人自助注册即获得教师权限。

**要求**：`/register/` 页面与 `POST /api/v1/auth/register/` 的角色选项**收敛为学生一种**；教师与管理员账号只能由管理端创建。
**兼容性**：`role` 字段保留（不删字段、不改接口签名），默认值本就是 `student`，所以显式传 `teacher` 的调用方会收到校验错误——需在 §6 待确认问题里确认是否有外部依赖。

## 7. 验收标准（GIVEN-WHEN-THEN）

### 7.1 导航与角色分离

- **AC-01** GIVEN 管理员已登录 WHEN 打开任意页面查看顶部导航 THEN 一级菜单仅含「首页/数据总览/用户管理/组织与基础数据/系统配置」+ 折叠的「教学管理（代管）」，**不含**题库、AI 出题、知识点、试卷、考试、批改、学情、作弊检测、班级作为一级项。
- **AC-02** GIVEN 管理员已登录 WHEN 展开「教学管理（代管）」THEN 出现上述 9 个二级入口，且点击后正常进入对应教师页面。
- **AC-03** GIVEN 管理员已登录 WHEN 进入任一教师页面 THEN 页面顶部出现常驻提示条"你正在以管理员身份代管教学功能"。
- **AC-04** GIVEN 教师已登录 WHEN 查看导航 THEN 仍是 9 个一级教学菜单，**看不到**数据总览、用户管理、系统配置。
- **AC-05** GIVEN 学生已登录 WHEN 查看导航 THEN 仅有 5 个学生菜单，无任何管理类或教学管理类入口。
- **AC-06** GIVEN 教师已登录 WHEN 直接在地址栏访问 `/manage/users/` THEN 302 重定向到首页并提示"该区域仅管理员可访问"。
- **AC-07** GIVEN 学生已登录 WHEN 访问 `/manage/` THEN 302 重定向到首页并提示，且不泄露该页面存在的内容。

### 7.2 管理员首页

- **AC-08** GIVEN 管理员已登录 WHEN 访问 `/` 或登录成功 THEN 落地到 `/manage/`，看到用户数/班级数/题库量/考试量四项指标与 AI 用量区块。
- **AC-09** GIVEN 管理员已登录 WHEN 打开数据总览 THEN 页面**不出现**任何一张教师业务快捷卡片（题库/组卷/批改等）。
- **AC-10** GIVEN 全新空库 WHEN 管理员打开数据总览 THEN 所有指标显示 `0`，图表区显示"暂无数据"，页面无报错。
- **AC-11** GIVEN 教师已登录 WHEN 访问首页 THEN 仍看到原有 8 张教学卡片 + 个人中心，与改造前完全一致。

### 7.3 用户管理

- **AC-12** GIVEN 管理员在用户列表 WHEN 输入关键词"张" THEN 只返回用户名/姓名/邮箱/学号/手机号中命中"张"的用户，且 URL 带 `search=张` 可刷新复现。
- **AC-13** GIVEN 管理员在用户列表 WHEN 选择角色=教师、状态=已停用 THEN 只返回同时满足两个条件的用户，清空筛选后恢复全量。
- **AC-14** GIVEN 管理员 WHEN 提交新建用户表单且用户名已存在 THEN 停留在表单页，用户名输入框下方报"该用户名已被占用"，其余已填内容不丢失。
- **AC-15** GIVEN 管理员 WHEN 新建用户时初始密码填 `123456` THEN 被拒绝并提示"密码不能全部为数字"或"该密码过于常见"。
- **AC-16** GIVEN 管理员 WHEN 打开某用户的编辑页 THEN 用户名为只读文本且提示创建后不可修改；状态字段不出现在表单中。
- **AC-17** GIVEN 管理员 WHEN 尝试把超级管理员角色改成教师 THEN 被拒绝并提示"超级管理员的角色不可降级"。
- **AC-18** GIVEN 系统仅剩一个启用状态的管理员 WHEN 尝试停用该账号 THEN 被拒绝并提示"系统至少保留一个启用的管理员"。

### 7.4 重置密码

- **AC-19** GIVEN 管理员 WHEN 点击某用户「重置密码」并选择随机生成 THEN 生成 12 位含字母与数字的密码，模态框展示一次并可复制。
- **AC-20** GIVEN 管理员 WHEN 手动输入新密码为纯数字或与用户名高度相似 THEN 被拒绝并给出对应策略提示。
- **AC-21** GIVEN 管理员已完成一次重置密码 WHEN 关闭模态框并刷新页面 THEN 新密码明文不再出现在任何位置。
- **AC-22** GIVEN 某用户被重置密码 WHEN 该用户用旧密码登录 THEN 失败；用新密码登录 THEN 成功。
- **AC-23** GIVEN 管理员 WHEN 在自己那一行查看操作列 THEN 「停用」「重置密码」为禁用状态并提示到个人中心操作。

### 7.5 启用 / 停用

- **AC-24** GIVEN 管理员 WHEN 点击「停用」THEN 弹出确认模态框，说明"该账号将立即无法登录，其数据保留不变"；取消后状态不变。
- **AC-25** GIVEN 某用户已被停用且此前保持页面登录 WHEN 该用户下一次发起页面请求 THEN 被强制登出并提示"账号已被停用，请联系管理员"。
- **AC-26** GIVEN 某用户已被停用 WHEN 该用户用**正确密码**登录 THEN 提示"该账号已被停用，请联系管理员"。
- **AC-27** GIVEN 某用户已被停用 WHEN 该用户用**错误密码**登录 THEN 提示仍为"账号或密码错误"（不泄露账号状态）。
- **AC-28** GIVEN 某用户已被停用 WHEN 该用户用旧 JWT 调任意接口 THEN 返回 401。

### 7.6 注册收敛

- **AC-29** GIVEN 匿名访客 WHEN 打开 `/register/` THEN 页面不提供"教师"角色选项，提交后创建的账号角色必为 `student`。
- **AC-30** GIVEN 匿名访客 WHEN 直接向 `POST /api/v1/auth/register/` 提交 `role=teacher` THEN 返回校验失败，不创建任何账号。

### 7.7 系统配置

- **AC-31** GIVEN 未配置任何 AI 密钥 WHEN 管理员打开 `/manage/system/` THEN 显示"当前为本地模拟模式（mock）"警示条，页面不报错。
- **AC-32** GIVEN 已配置 DeepSeek 密钥 WHEN 管理员打开系统配置 THEN 显示"DeepSeek：已配置"，且**页面源码与响应体中均不含密钥明文**。

### 7.8 回归与非功能

- **AC-33** GIVEN 现有 781 个测试用例 WHEN 执行 `python manage.py test` THEN 全部通过，且未修改任何既有断言。
- **AC-34** GIVEN 本期改动 WHEN 执行 `python manage.py makemigrations --check --dry-run` THEN 输出"no changes"（P0 零迁移）。
- **AC-35** GIVEN 管理端任一页面 WHEN 在 375px 宽度下打开 THEN 内容可读、无横向滚动溢出，操作按钮可点。
- **AC-36** GIVEN 用户列表 1 万条数据 WHEN 加载首页 THEN 首屏渲染 < 1.5s，请求数 ≤ 2（列表 + 候选项）。
- **AC-37** GIVEN 任一危险操作（重置密码/停用/改角色）WHEN 用 GET 请求访问对应 URL THEN 返回 405，不产生任何状态变更。

## 8. 非功能要求与回归保障

| 类别 | 要求 |
|---|---|
| **既有功能零破坏** | 教师端与学生端的页面、导航、接口行为一律不变；现有 **781 个后端测试必须继续全部通过**，且不允许修改既有断言来"迁就"新需求 |
| **数据库** | P0 **零迁移**。不新增表、不改字段。所有 P0 需求仅用现有 `users` / `classroom` / `questions` / `papers` / `exam` / `ai_request_log` 表 |
| **接口纪律** | 统一响应体 `{code,message,data}`；页面走 Session + CSRF，接口走 JWT；新增接口必须进 Swagger（`@extend_schema`）并带 tags |
| **安全** | 不在任何页面/响应/日志中回显 AI 密钥或密码明文；危险操作一律 POST + CSRF；不引入账号枚举（停用提示需先验证密码正确）；沿用"跨人访问返回 404 而非 403"的既有纪律 |
| **技术栈一致性** | 服务端渲染模板 + Bootstrap 5 + 原生 JS + ECharts，不引入前端构建工具；不改动 DRF 版本与分页/过滤器约定 |
| **性能** | 数据总览全部指标单接口返回，走 `aggregate`，目标 < 300ms；用户列表沿用 `StandardPagination`（`page_size` 默认 10，上限 100） |
| **可维护性** | 权限判定集中在 `apps/common/permissions.py` 与管理端 mixin，不在模板里散落 role 判断 |
| **国际化** | 全部文案中文，与现有一致 |
