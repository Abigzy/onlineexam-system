### 1.3 术语

| 术语 | 含义 |
|---|---|
| 知识点 | 可成树的学科知识点（`KnowledgePoint`），题目挂在其上；掌握度会**向上归并**到祖先节点 |
| 题型 | `single` 单选 / `multiple` 多选 / `judge` 判断 / `fill` 填空 / `short` 简答 / `essay` 论述 |
| 难度 | 1 简单 / 2 中等 / 3 困难 / 4 挑战 |
| 客观题 | 单选 / 多选 / 判断（可精确匹配判分） |
| 主观题 | 简答 / 论述（AI 语义评分 + 人工复核）；填空按客观题处理但答案存在 `answer_text` |
| 掌握度 | 某学生在某知识点上的正确率（客观题）或得分率（主观题） |
| 薄弱知识点 | 掌握度低于 `WEAKNESS_RATIO=0.60` **且**样本数 ≥ `MIN_SAMPLES_FOR_WEAKNESS=2` |
| 作答（attempt） | 学生参加一场考试的一次记录，`ExamAttempt` |
| 证据链 | 某次作答的逐条行为埋点 + 命中规则 + 异常分的完整可查记录 |

## 2. 项目概述（源自需求原文）

> 构建一个集**教师出题、智能组卷、在线考试、AI 自动批改、学情分析与个性化推荐**于一体的
> 在线考试平台。AI 的加入让系统从传统的"答题工具"升级为"智慧教学助手"。

需求原文提出的五大块：

1. **基础功能**：三角色、六种题型题库、手动组卷、限时答题/自动计时/防切屏/断网续考、
   客观题自动判分 + 主观题人工复核；
2. **AI 智能组卷**：输入知识点范围 + 期望难度 + 题量，自动抽题，
   保证知识点覆盖均衡、难度梯度合理，ECharts 展示知识点雷达图与难度分布直方图；
3. **AI 自动批改**：客观题精确匹配；主观题按相似度阈值给分（≥0.7 满分、0.4~0.7 部分分、
   <0.4 不得分），支持教师复核改分并反馈给模型；
4. **学情分析与个性化推荐**：知识点掌握度、薄弱环节识别、成绩趋势预测（线性回归），
   ECharts 画雷达图 / 正态曲线 / 得分率柱图 / 趋势折线；按薄弱知识点推荐练习题
   （协同过滤或内容推荐）；
5. **作弊行为检测**：监控鼠标离开窗口次数、粘贴行为、答题时间异常，
   用规则引擎或孤立森林标记可疑考生。

## 3. 用户角色与权限

| 角色 | 标识 | 定位 |
|---|---|---|
| 管理员 | `admin` | 用户管理（增删改查、改角色）、系统级数据维护 |
| 教师 | `teacher` | 题库 / 知识点 / 试卷 / 考试 / 判分 / 学情 / 作弊检测 |
| 学生 | `student` | 参加考试、查看自己的成绩与学情、每日练习 |

### 3.1 权限矩阵（业务模块 × 角色）

| 模块 | 管理员 | 教师 | 学生 |
|---|---|---|---|
| 用户管理 | ✅ 全量 | ❌ | 仅本人（`me` / 改密码） |
| 题库 / 知识点 | ✅ | ✅ 全量 | ❌（仅在考试下发时拿到题目） |
| 试卷与组卷 | ✅ | ✅ 全量 | ❌ |
| 考试管理（建/发/归档） | ✅ 全量 | ✅ 全量；**「面向全体」只覆盖自己可管理班级的学生**（FR-6-10） | 仅"我的考试"列表，且已按参与范围过滤 |
| 在线答题 | ❌ | ❌ | ✅ 本人 |
| 判分 / 复核 / 出分 | ✅ | ✅ 全量 | ❌ |
| 成绩单 / 错题本 | ✅ | ✅ 全量 | 仅本人 |
| 学情分析 | ✅ 全量 | 仅**自己带的班**里的学生（班外 404） | 仅本人 |
| 每日练习推荐 | ❌ | 可查任意学生（教师身份） | ✅ 仅本人 |
| 作弊检测 | ✅ | ✅ 全量 | ❌ |

> **跨人访问一律返回 404 而不是 403**：不让学生拿状态码当"这个 id 是否存在"的探针
> （模块五/六/七/八共用同一条纪律）。

## 4. 功能需求

### FR-1 用户与认证（模块 1）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-1-1 | 注册：用户名 / 邮箱 / 年级 + 密码，校验强度与唯一性；**学号由系统按年级顺位派发** | `POST /api/v1/auth/register/`，角色由服务端决定，不接受前端传 role 与 student_no |
| FR-1-2 | 登录：支持**用户名 / 邮箱 / 学号**三种方式 | 自定义 `AuthBackend`；返回 JWT（access + refresh） |
| FR-1-3 | JWT 无状态鉴权，refresh 可续期、logout 使 refresh 失效 | SimpleJWT；`logout` 走黑名单 |
| FR-1-4 | 当前用户 `/me/`、修改密码 | 需登录；改密码要校验原密码 |
| FR-1-5 | 管理员可管理全部用户（含改角色） | `IsAdmin` |

### FR-2 AI 适配层（模块 2A）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-2-1 | 统一封装多家大模型，业务层不感知厂商差异 | `apps/ai/providers/`，DeepSeek 为主 |
| FR-2-2 | 无 Key / 调用失败时**自动降级 mock**，功能不中断 | `build_provider()`；**测试环境强制 mock** |
| FR-2-3 | 每次调用落日志（provider / model / 场景 / token / 耗时 / 成功与否 / 是否 mock） | `AIRequestLog`，供用量统计与排障 |
| FR-2-4 | 提供连通性自检与用量统计接口 | `ai/test-connection/`、`ai/usage/`（教师） |

### FR-3 知识点管理（模块 2B）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-3-1 | 知识点**成树**（父子），按学科归类，可排序 | `KnowledgePoint.parent` 自关联，带环保护 |
| FR-3-2 | 树形接口、按知识点查题目、启停 | `knowledge-points/tree/`、`{id}/questions/` |
| FR-3-3 | 删除知识点：**子树内还有在用题目时拒绝**（code 12030）；没有题目才允许删除，连子节点一起删 | 检查范围是**整棵子树**而非只看自己——父节点是 CASCADE，删它会连带删子节点，子节点上的题目会静默失去知识点归属。删除是**物理删除**（不是软删），响应里如实返回「含 N 个子知识点」；已停用的题目不阻塞 |

### FR-4 题库管理（模块 2B / 2D）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-4-1 | 支持**六种题型**：单选、多选、判断、填空、简答、论述 | `QuestionType` 六值 |
| FR-4-2 | 题目含题干 / 选项 / 参考答案 / 解析 / 难度 / 分值 / 学科 / 知识点 | `Question` + `QuestionOption` |
| FR-4-3 | 增删改查 + 按知识点/题型/难度/学科筛选 + 分页 | DRF + django-filter |
| FR-4-4 | **AI 智能出题**：粘贴教材文本或仅给知识点，批量生成题目 | `questions/ai-generate/`；输出当不可信输入，能修就修、修不了丢进 `errors` |
| FR-4-5 | **Excel 批量导入 / 导出**（含模板下载） | `questions/import/`、`export/`、`import-template/` |
| FR-4-6 | 删除为**软删除**（`is_active=False`），保护历史试卷可追溯 | 硬删除会破坏历史卷子 |
| FR-4-7 | 统计：题型/难度分布、家底矩阵 | `questions/statistics/` |

### FR-5 试卷与组卷（模块 3）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-5-1 | 试卷为**三层结构**：试卷 → 大题 → 卷内题目 | `Paper` → `PaperSection` → `PaperQuestion` |
| FR-5-2 | 卷内题目存**分值/题型/难度快照**，题库改题不影响历史卷 | 快照是刻意的冗余 |
| FR-5-3 | 手动组卷：按知识点 / 难度 / 题型挑题，支持调分、排序、增删 | 组卷工作台三栏页面 |
| FR-5-4 | **AI 智能组卷**：给知识点范围 + 期望难度 + 题量，自动抽题并保证覆盖均衡、难度梯度合理 | `papers/ai-compose/`；**算法定题、LLM 只写组卷说明**，`dry_run` 先看方案 |
| FR-5-5 | **随机组卷（不调 AI）**：只勾知识点 + 题量，「一键」出卷；题型配比由题库库存自动决定，不消耗大模型调用 | `papers/random-compose/`；`PaperComposeService.auto_blueprint()` 按库存占比分配题型题量、超库存封顶；`generation_mode=random`，**不生成 AI 组卷说明**；`seed` 可复现 |
| FR-5-6 | 组卷质量可视化：知识点分布雷达图、难度分布直方图 | ECharts，`papers/{id}/analysis/` |
| FR-5-7 | 试卷试算 / 预览 / 克隆 / 发布 / 导出 | `papers/{id}/preview/`、`clone/`、`export/`、`status/` |

### FR-6 在线考试（模块 4）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-6-1 | 限时答题：服务端算 `deadline_at`，前端只做展示 | **服务端是唯一计时权威** |
| FR-6-2 | 自动计时；超时自动交卷，留 30 秒宽限 | `SUBMIT_GRACE_SECONDS=30` |
| FR-6-3 | **防切屏提醒**并记录次数，超限可按配置强制交卷 | `detect_switch` / `max_switch_count` / `auto_submit_on_limit` |
| FR-6-4 | **断网续考**：刷新/换设备题序一致，作答已保存 | 种子 `shuffle_seed` 落在 attempt 上；`attempts/{id}/save/` |
| FR-6-5 | 题目/选项乱序（可配） | `shuffle_questions` / `shuffle_options` |
| FR-6-6 | **答案防泄漏**：下发的题目里根本没有答案与解析字段 | `QuestionStudentSerializer` 白名单，不靠前端隐藏 |
| FR-6-7 | 心跳保活、行为上报（切屏/粘贴/退出全屏/失焦） | `attempts/{id}/heartbeat/`、`behavior/` |
| FR-6-8 | 考试状态：草稿 / 已发布 / 进行中 / 已结束 / 已归档 | 「进行中」**按时间实时算**，不落库 |
| FR-6-9 | 教师监控看板：实时作答进度与切屏预警 | `/exams/{id}/monitor/` |
| FR-6-10 | **「面向全体」按创建者收窄参考范围**：教师创建的考试只对该教师**可管理班级**（自己创建 / 任班主任 / 在授课名单里）的学生开放；管理员创建或无创建人时才是全校在册学生。班外学生**看不到该考试、也无法开考** | `Exam.open_to_all_scope()`，同时作用于学生可见列表（`ExamQuerySet.for_student`）、开考校验（`Exam.open_to`）与应考人数（`participant_count`）。学科归属已隐含在班级关系里，不再按 `subject` 二次过滤 |

### FR-7 判分与成绩（模块 5）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-7-1 | **客观题精确匹配自动判分** | `ObjectiveGradingService`，纯函数、不写库不调 AI |
| FR-7-2 | 多选支持三种策略：全对才得分 / 漏选比例分 / 错选扣分 | `Exam.multiple_choice_policy`（strict/partial/penalty） |
| FR-7-3 | **主观题 AI 语义评分**：≥0.7 满分、0.4~0.7 线性插值、<0.4 不得分 | `apps/ai/schemas.score_by_threshold()` |
| FR-7-4 | 教师**人工复核改分**，记录"谁把哪题从多少改到多少" | `GradingFeedback` 审计表 |
| FR-7-5 | 总分 = 客观 + 主观，只有**一个写入口**且每次重算（幂等） | `GradingService.recalc()` |
| FR-7-6 | 出分并公开成绩；出分前必须先判客观题（防"全班 0 分"） | `finalize` |
| FR-7-7 | 成绩单（学生个人 / 班级）、错题本 | `scoreboard/`、`wrong-book/`、`attempts/{id}/report/` |
| FR-7-8 | AI 批改校准统计（AI 分 vs 教师分的偏离） | `grading/calibration/` |
| FR-7-9 | **AI 批改是花钱动作**：不带 `with_ai` 只判客观题 | 工作台上是两个不同按钮 |
| FR-7-10 | 成绩可见性：`graded` 必可见；`auto_graded` 仅当考试配置"立即公布" | 防"教师出分了学生还看不到" |

### FR-8 学情分析（模块 6）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-8-1 | **知识点掌握度**（基于答题正确率矩阵），且**向上归并**到祖先知识点 | 只算叶子会让顶层永远为空 |
| FR-8-2 | **薄弱环节识别**：掌握度 <0.60 且样本 ≥2 才算薄弱 | 样本不足标 `UNKNOWN`，不给结论 |
| FR-8-3 | **成绩趋势预测**：线性回归 + 方向判定，≥3 个数据点才预测 | `TrendService.linear_fit` |
| FR-8-4 | 班级维度：分数段分布 + 正态曲线、逐题得分率、**区分度**（前后 27% 得分率差） | `ExamAnalyticsView` |
| FR-8-5 | 可视化：个人知识雷达图、班级正态曲线、得分率柱图、趋势折线 | ECharts，服务端给 `{indicator,values}` 等结构 |
| FR-8-6 | **AI 学情诊断报告**：数字由代码算、话由模型说；24h 缓存 | GET 不调模型，`POST diagnosis/` 才调 |

### FR-9 个性化推荐（模块 7）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-9-1 | 按薄弱知识点推荐针对性练习题（内容推荐） | 匹配度 = `(0.65×薄弱度 + 0.35×难度适配度) × (1 + 0.30×协同分)` |
| FR-9-2 | 协同过滤（学生-题目得分矩阵） | item-based 余弦相似度；**冷启动自动退化**为纯内容推荐 |
| FR-9-3 | 难度适配：越接近"略高于当前水平"越好，避免过难打击信心 | `difficulty_fit(d, target) = max(0, 1 - |d-target|/3)` |
| FR-9-4 | 同一知识点不连续堆叠（≤2 题） | `MAX_PER_KNOWLEDGE_POINT=2` |
| FR-9-5 | "为什么推这道题"落成可读的一句话 | 本地规则理由；`POST` 才让模型改写（**选题仍由算法定**） |
| FR-9-6 | 每日练习：当天刷新不换题、跨天轮换；"换一批"不重复 | 确定性函数 `md5(学生|日期|题目)`，**不建表** |

### FR-10 作弊行为检测（模块 8）

| 编号 | 需求 | 实现要点 |
|---|---|---|
| FR-10-1 | 监控**鼠标离开窗口次数**（切屏/失焦） | 逐条埋点 `ExamBehaviorLog` |
| FR-10-2 | 监控**粘贴行为** | 同上，`paste` 事件 |
| FR-10-3 | 监控**答题时间异常**（过快/过慢） | 规则 `answer_too_fast`；单题耗时与每题均值 |
| FR-10-4 | 规则引擎标记可疑考生，阈值可配、**唯一定义处** | `RULE_CATALOG` 9 条规则，`apps/proctoring/constants.py` |
| FR-10-5 | **孤立森林**做无监督异常检测，补充规则覆盖不到的离群 | sklearn；样本 <8 不训练；`random_state=42` 保证可复现 |
| FR-10-6 | 可疑考生列表 + **证据链**（逐条可查"因为什么"） | 每条信号带 `code/name/reason/evidence` |
| FR-10-7 | 埋点只存事实、不存结论；结论读时现算 | 改阈值后历史结论不过时 |

## 5. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-1 | 规范 | 对外 API 遵循 RESTful：GET 安全幂等、POST 创建/动作、PUT 全量、PATCH 局部、DELETE 删除 |
| NFR-2 | 规范 | 统一响应体 `{code, message, data}`；`code=0` 成功，4xxxx/5xxxx 对应 HTTP 状态 ×100，10001+ 为业务语义错误 |
| NFR-3 | 安全 | 学生侧接口与页面**不得下发**答案、解析、正确选项标记；**成绩未公开时也不得下发得分与逐题对错**（`score` / `passed` / `is_correct` 一律 `null`）。可见性唯一口径 `ExamAttempt.score_visible()`：**`graded` 恒可见**（出分即发布）、`auto_graded` 看 `show_score_immediately`、其余不可见 |
| NFR-4 | 安全 | 跨人访问返回 404 而非 403；JWT 无状态；密码不明文存储 |
| NFR-5 | 健壮性 | AI 能力一律**降级不抛异常**：模型不可用 / 返回脏数据 → 退化为本地策略并标记 `degraded` |
| NFR-6 | 健壮性 | 参数校验失败返回 400，不允许 500；未知异常统一转业务错误码 |
| NFR-7 | 可复现 | 所有随机（组卷抽题、推荐排序、异常检测）**都由种子决定**，同样输入必得同样输出 |
| NFR-8 | 可维护性 | 阈值 / 权重 / 规则目录集中在各模块的 `constants.py`，一处定义、多处读取 |
| NFR-9 | 性能 | 聚合类接口避免 N+1（批量查 + `select_related`）；列表接口全部分页 |
| NFR-10 | 兼容 | MySQL 5.6 兼容：无原生 JSON 字段，结构化小数据一律 `TextField` 存 JSON 字符串 |
| NFR-11 | 数据 | 埋点为"写多读少"，按 180 天保留并可裁剪；软删除保护历史可追溯 |
| NFR-12 | 数据一致性（**已知局限**） | 学号 / 工号由系统按「同类最大值 +1 再查重」派发，**没有数据库唯一约束**——`student_no` 允许为空，而 MySQL 5.6 不支持「非空时唯一」的条件索引。极端并发（同一时刻多人注册）仍可能撞号；要强一致需升 MySQL 8.0 并加函数索引 |
