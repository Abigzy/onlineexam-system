# 开发路线图

> 本文件是整个项目的「施工图」。**每完成一个模块就打勾**，新会话开始时先读这里就知道做到哪了。
> 配套的实时进度见 [`进度记录.md`](./进度记录.md)。

## 设计原则

1. **一个模块一个 app**：`apps/<domain>/`，自带 models / serializers / views / urls / services / tests。
2. **胖模型、瘦视图**：查询逻辑上收到自定义 QuerySet，多步业务上收到 Service 层并包事务。
3. **接口先定、页面后贴**：每个模块先出 RESTful 接口（可在 Swagger 里直接验证），再补页面。
4. **AI 能力统一走适配层**：业务代码永不直接写 HTTP 调用大模型的代码，只调 `apps.ai.services`。
5. **每个模块自带测试**：`python manage.py test apps.<domain>` 必须全绿才算完成。

**目标**：先把「调大模型」这件事收进一个地方，再在它之上盖题库。

### 2.1 AI 适配层 `apps/ai/`

- [x] `providers/base.py` —— `BaseProvider` 抽象（`chat()` / `chat_json()`）+ `ChatResult`

- [x] `providers/__init__.py` —— `PROVIDER_CATALOG`（四家平台的 base_url / 默认模型 / 环境变量名）

- [x] `schemas.py` —— 结构化输出校验：`parse_generated_questions()` / `parse_grading_result()` /

- [x] `models.py` —— `AIRequestLog`（provider / model / 场景 / tokens / 耗时 / 成功 / 是否 mock / 错误摘要）
- [x] 接口：`POST /ai/chat/`（调试）、`POST /ai/test-connection/`、`GET /ai/providers/`、
      `GET /ai/usage/`、`GET /ai/logs/`
- [x] `mocks.py` —— mock 场景处理器（出题 / 判分 / 知识点抽取等），用 bigram Dice 相似度兜底评分

**关键设计**：**大模型输出一律当作「不可信输入」**——能修复就修复（补缺失字段、纠正题型），

### 2.2 题库 `apps/questions/`

- [x] `KnowledgePoint` 知识点树（自关联多级 + `full_path` / `level` / `descendant_ids()`）
- [x] `Question` 题目（单选/多选/判断/填空/简答/论述 + 难度 + 分值 + 解析 + 知识点 M2M + 创建人 + 使用/正确率统计）
- [x] `QuestionOption` 选项（label / content / is_correct / order）
- [x] 接口：题目 CRUD + 按题型/难度/知识点（**含子知识点**）/关键字/来源筛选
- [x] 批量导入导出：CSV（**带 UTF-8 BOM**，防 Excel 乱码）/ XLSX；多值字段用 `|` 分隔；带导入模板下载
- [x] **AI 辅助出题**：教材段落 → 生成草稿（返回给前端编辑）→ 教师确认后批量入库
- [x] AI 补解析（`ai-explain`）、主观题 AI 试评（`ai-grade`）
- [x] `GET /questions/statistics/` —— 题型/难度/来源/知识点分布 + 平均难度系数 + 审核率
- [x] 页面 4 个：题库列表（筛选/分页/导入导出）、题目编辑器（按题型动态渲染）、
      AI 出题工作台（生成 → 编辑 → 入库）、知识点树管理
- [x] `seed_questions` 管理命令：20 个知识点 + 19 道样题（《数据结构》）
- [x] **48 个测试用例全部通过**（`apps/ai` 52 个 + `apps/questions` 48 个，合计 129 个全绿）

**关键设计**：
1. **答案防泄漏靠序列化器分层，不靠前端隐藏**——`QuestionStudentSerializer` 里根本没有
   `reference_answer` / `analysis` / `options[].is_correct` 这些字段，考试模块直接用它下发试卷。
2. **软删除**：DELETE 题目 = `is_active=False`（停用），不物理删除，避免破坏历史试卷与成绩的可追溯性。
3. **知识点不存在就自动创建**，教师粘贴 AI 草稿时不用先手动建树。

## 模块 3 · 试卷与组卷 ✅

**目标**：把「题库」变成「卷子」。手动能编，AI 能组，组完看得见质量。

### 3.1 三层试卷模型 `apps/papers/`

- [x] `Paper`（卷头：标题 / 学科 / 总分 / 及格分 / 时长 / 目标难度 / 状态 / 组卷方式 / 创建人）
- [x] `PaperSection`（大题分区：一、单项选择题……，带答题说明与每题分值）
- [x] `PaperQuestion`（卷内题目：题序 / 分值快照 / 题型快照 / 难度快照）
  - 快照的意义：题库里改一道题，历史卷子不能被悄悄改掉
- [x] `PaperQuerySet`：`active()` / `published()` / `search()` / `with_relations()` / `with_counts()`
- [x] 软删除 + 唯一约束 `uniq_paper_question`（同一卷内同一题只能出现一次）
- [x] 冗余汇总字段 `total_score` / `question_count` / `section.score_per_question`，
      统一由 `PaperService.recalc()` 维护，避免各处各算一遍

### 3.2 手动组卷 `PaperService`

- [x] `create` / `update` / `delete`（已发布不能删，只能退回草稿或归档）
- [x] `add_questions`（`strict=True` 遇重复报错，`strict=False` 静默跳过，供组卷算法用）
- [x] `remove_questions`（按 `PaperQuestion.id` 定位，避免误删别卷的题）
- [x] `set_score` / `batch_set_score` / `reorder`（做题序）
- [x] `sync_sections`：自动补建/清理大题分区、回填分值、把题目归位
- [x] `renumber`：全卷连续编号
- [x] `clone`：一键复制做 A/B 卷
- [x] `change_status`：发布前校验空卷、及格分不高于总分

### 3.3 AI 智能组卷 `PaperComposeService`

**算法定正确性，LLM 只负责可解释性** —— 选哪些题是可验证的，不该交给大模型。

- [x] `DEFAULT_BLUEPRINT`：单选 10×2 + 多选 5×3 + 判断 10×1 + 填空 5×2 + 简答 3×10 + 论述 1×15 = 100 分
- [x] **难度配比插值**：三角核 `w(d) = max(0, 1 - |d - target| / 1.5)`，
      目标 2.0 时就是「中等为主、相邻难度递减」
- [x] **最大余数法**切分配额，保证各档整数和恰好等于题量（不会多一道少一道）
- [x] **库存感知的配额再平衡** `_rebalance_quota`：先把超出库存的配额削掉，
      再按离目标难度由近及远补到还有余量的档位（提前预判，比留到最后乱补准得多）
- [x] **知识点轮转** `_kp_cost`：优先抽本卷用得最少的知识点，避免一份卷子反复考同一个点
- [x] **难度回退补位**：某档库存不足时向相邻难度补齐，并单独记进 `adjusted` 让教师知情
- [x] `preview()` 试算（不落库）与 `compose()` 落库，**两条路径返回同一套报告字段**
- [x] `seed` 参数：传相同值可复现同一份卷子
- [x] `describe_pool()`：题型 × 难度库存矩阵（工作台左侧的「题库家底」）
- [x] **组卷说明**：`PaperAIService.generate_notes()` 把分析报告转成提示词变量，
      存入 `Paper.ai_notes`（`force=False` 时命中缓存不重复调模型）

### 3.4 组卷质量分析 `PaperAnalysisService`

- [x] `overview` / `type_distribution` / `difficulty_distribution`（四档全列含 0）
- [x] `knowledge_coverage`：雷达图数据 + 覆盖率 + 未覆盖清单（含子知识点）
- [x] `section_stats`：每个大题的题量 / 分值 / 平均难度
- [x] `warnings` 六类预警：空卷、难度偏差超容差、知识点覆盖率不足、及格分异常、
      题型单一、时长与题量不匹配
- [x] `full_report`：一次给全，工作台少发几个请求

### 3.5 接口与页面

- [x] RESTful：试卷 CRUD + `questions` / `remove-questions` / `scores` / `reorder` /
      `clone` / `status` / `preview` / `analysis` / `ai-notes` / `export` /
      `ai-compose` / `pool` / `statistics`
- [x] 导出 HTML（A4 打印 CSS，答案页自动分页）/ Markdown
- [x] 页面：试卷列表、**三栏组卷工作台**（左=条件+知识点树+蓝图+题库家底；
      中=卷面预览可调分/换序；右=ECharts 雷达图+难度分布+预警+AI 说明）
- [x] 学生视角序列化器 `PaperQuestionStudentSerializer`（借 `student_payload()` 防答案泄漏）
- [x] `seed_papers` 生成 3 份演示卷
- [x] **114 个测试用例**（服务层 + 组卷算法 + 分析 + 接口权限 + 生命周期）

## 模块 4 · 在线考试 ✅

**目标**：把「一张卷子」变成「一场考试」——限时、可控、可断点续考、行为可追溯。

### 4.1 三张表 `apps/exam/`

- [x] `Exam` 考试：时间窗（`start_time` / `end_time`）、时长（0 = 沿用试卷）、及格分覆盖、
      作答次数上限、题目 / 选项乱序、防作弊开关组（切屏检测 + 上限 + 超限强制交卷、
      粘贴检测、要求全屏）、断网续考开关、参考范围（面向全体 / 指定考生）
- [x] `ExamAttempt` 作答记录：状态机、**计时锚点 `started_at` / `deadline_at`**、
      满分快照、各项得分字段（模块五填充）、题量 / 已答数、
      行为计数（切屏 / 粘贴 / 退出全屏 / 心跳）、IP 与 UA、超时与交卷原因、乱序种子
- [x] `Answer` 作答明细：`selected_labels`（选项字母，已排序去重）+ `answer_text`（填空按行 / 主观题整段）、
      标记待复查、`is_correct`（**null = 未判分**）、得分占位、AI 建议分与评语占位
- [x] 唯一约束：`uniq_attempt_exam_student_no`（同一场同一人同一轮次只有一条）、
      `uniq_answer_attempt_question`（一题一条作答）
- [x] 索引覆盖「按考试看状态」「按学生看历史」「按题目聚合得分率」三条主要查询路径

### 4.2 服务层 `ExamService` / `ExamAttemptService`

**两条不可让步的纪律**：

1. **服务端是唯一计时权威。** `deadline_at` 在开考那一刻算好落库（并被考试结束时间封顶），
   之后所有判断都读它。前端倒计时只负责显示，心跳时上报的客户端剩余时间只作为
   「时钟漂移」观测值记下来，**绝不参与判据**。
2. **答案过滤只有一个出口。** `_question_payload()` 只转出 `student_payload()` 的
   白名单字段；工作台模板与接口都只走它。评审这条链路时看一个函数就够了。

- [x] `start()`：开考 / **续考优先**（已有进行中的作答直接复用，这就是断网续考的落地点）
- [x] 次数上限校验、参考范围校验、时间窗校验、截止时间封顶
- [x] `build_paper_payload()`：卷面下发（大题分组 + 扁平列表双形态，一屏一题与全卷模式共用）
- [x] `get_state()`：刷新 / 重连时拉回**已存答案 + 权威剩余时间**，并顺带做超时结算
- [x] `save_answers()` 批量暂存 / `save_answer()` 单题暂存；选项字母标准化（大写 + 去重 + 排序）
- [x] `heartbeat()`：返回服务端剩余时间 + 时钟漂移 + 是否需要交卷
- [x] `record_behavior()`：切屏 / 粘贴 / 退出全屏计数，超限判定与（可选）强制交卷
- [x] `submit()`：**幂等**（重复交卷不覆盖首次交卷时间）、自动判超时、结算已答数与用时
- [x] `resolve_expiry()`：连宽限期都过了就自动收卷（学生关页面拖到超时也不会「还在答题中」）
- [x] **交卷宽限期 `SUBMIT_GRACE_SECONDS=30`**：网络抖动下点交卷不至于被判超时，
      又不至于让「超时后继续答题」变得有利可图
- [x] 乱序是**确定性**的：种子落在 attempt 上，刷新 / 换设备 / 断网重连看到的题序完全一致
      （否则「第 5 题」到底指哪道题就说不清了）
- [x] 状态机：草稿 → 已发布 → 进行中 → 已结束 → 已归档；
      已发布 + 在时间窗内由 `computed_status()` 实时算出「进行中」，不必写库

### 4.3 接口

- [x] 考试 CRUD + `status`（发布 / 开始 / 结束 / 归档）+ `overview`（单场统计）
      + `attempts`（作答明细看板）+ `statistics`（总览）+ `candidates`（选考生）
- [x] `POST /exams/{id}/start/` 开考下发（**剔除答案**）

## 模块 7 · 个性化推荐 ✅

- [x] 基于薄弱知识点的内容推荐（知识点薄弱度 × 难度适配度 → 匹配度排序）

> 落地要点：**不建新表**——推荐清单是确定性算出来的（同一学生 + 同一天 = 同一份清单，
> 顺序也一致），所以刷新页面不会换题，也就不需要用一张表去缓存它。三条纪律：
> ① 输入只有「模块五的判分结果」与「模块六的 `student_mastery()`」，**绝不在这里重算
> 掌握度**；② 样本不足不给推荐（门槛沿用 `MIN_SAMPLES_FOR_WEAKNESS`，只做过 1 题的
> 知识点永远不会变成一次推荐）；③ 协同过滤以**乘数**形式参与
> （`match = 内容分 × (1 + 30% × 协同分)`），算不出相似度时等价于「没有额外证据」，
> 匹配度依然可比——做成加权平均的话，冷启动会把所有题的分数一起拉低。

> GET 返回本地理由且**绝不调大模型**，`POST .../practice/` 才让模型改写理由并缓存 24h，

## 模块 8 · 作弊行为检测 ✅

- [x] 行为埋点表 `ExamBehaviorLog`（切屏、粘贴、退出全屏、失焦；含时长 / IP / 设备 / 题号）

- [x] 可疑考生列表 + 证据链详情页（教师侧）

> 落地要点：**只新增一张 `ExamBehaviorLog` 表**——模块四只在 `ExamAttempt` 上做聚合计数，
> 逐条明细（几时切屏、离开多久、当时在做哪道题）是有意留给模块八的，两个粒度需求不同。
> **这张表只存事实、不存结论**：切屏几次是客观事实，「算不算可疑」依赖可配的阈值，
> 所以结论一律由规则引擎**读的时候现算**（与模块六「学情统计是只读模型」同源），
> 教师改阈值后历史结论不会过时。三条纪律：① **只读不重算**——埋点缺失时用
> `ExamAttempt` 的聚合计数兜底（取 `max`），绝不反过来改考试模块的计数；
> ② **结论必须可解释**——每条可疑信号都带 `code / name / reason / evidence`，
> 教师点开红色标记一定能看到「因为什么」；③ **样本不足不给结论**——一场考试少于
> `ANOMALY_MIN_SAMPLES(8)` 份作答时不训练模型，老实说「不够判」。
> 埋点入口复用模块四的 `ExamAttemptService.record_behavior()`（惰性 import + 失败不阻断，
> 埋点自己也包在保存点里），并保证「埋点聚合」与「聚合计数」永远对得上。
> 异常检测与规则的**分工**：规则负责「可解释的坏」（阈值写在代码里），
> 孤立森林负责「不像别人的」（无监督兜底）；未安装 scikit-learn 时降级为
> 纯 Python 的稳健 z-score（median + MAD，MAD 为 0 时退化为标准差），功能不中断、
> `method` 字段如实告知。阈值全部集中在 `apps/proctoring/constants.py`。
> 验收：全量测试 **737 passed**（proctoring 84 个）；端到端冒烟模块八 10 项全过；
