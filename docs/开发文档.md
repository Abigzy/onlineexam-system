## 2. 系统架构

```
┌──────────────────────────────────────────────────────────┐
│ 浏览器：Django 模板页面（Session 登录）                    │
│        Bootstrap 5 + 原生 fetch + ECharts                │
└───────────────┬──────────────────────┬───────────────────┘
                │ 页面请求              │ AJAX（同源 /api/v1）
┌───────────────▼──────────┐  ┌────────▼───────────────────┐
│ views_pages.py           │  │ views.py（DRF）             │
│ 角色 mixin 拦截，只渲染   │  │ 鉴权 + 参数校验 + 序列化     │
└───────────────┬──────────┘  └────────┬───────────────────┘
                └──────────┬───────────┘
                    ┌──────▼───────────────────────┐
                    │ services.py（业务与聚合口径）  │
                    │ 多步写操作 @transaction.atomic │
                    └──────┬───────────────────────┘
                    ┌──────▼───────────┐  ┌──────────────┐
                    │ models.py        │  │ apps/ai      │
                    │ + 自定义 QuerySet │  │ 大模型适配层  │
                    └──────┬───────────┘  └──────────────┘
                    ┌──────▼───────────┐
                    │ MySQL            │
                    └──────────────────┘
```

**分层铁律**：

- 视图**要瘦**：只做鉴权 + 参数校验（Serializer）+ 调 Service + 包装响应；
- 查询逻辑放**自定义 QuerySet**（写在 `models.py` 里），不在视图里拼 `filter()` 长链；
- 多步业务放 **Service**，写操作加 `@transaction.atomic`；
- 派生汇总值只留**一个写入口**，且**每次重算**而不是累加（幂等来自"重算"）。

## 4. 环境搭建

### 4.1 安装

```bash
cd OnlineExam
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

> **必须用 `.venv\Scripts\python.exe`** 执行所有命令；全局 `python` 里没有 Django。

### 4.2 `.env` 配置

复制 `.env.example` 为 `.env` 后按需改。关键项：

| 变量 | 默认 | 说明 |
|---|---|---|
| `DJANGO_SECRET_KEY` | dev 兜底 | **生产必须改** |
| `DJANGO_DEBUG` | True | 生产置 False |
| `DB_ENGINE` | `sqlite` | 填 `mysql` 走 MySQL |
| `DB_NAME` / `DB_USER` / `DB_PASSWORD` / `DB_HOST` / `DB_PORT` | online_exam / root / 空 / 127.0.0.1 / 3306 | |
| `DB_CHARSET` | `utf8mb4` | **MySQL 5.6 要填 `utf8`** |
| `DB_SKIP_VERSION_CHECK` | — | MySQL 5.6 需要（Django 4.2 官方不支持） |
| `AI_PROVIDER` | `deepseek` | deepseek / doubao / yuanbao / openai / mock |
| `DEEPSEEK_API_KEY` / `_BASE_URL` / `_MODEL` | — | 各 provider 同理 |
| `AI_TIMEOUT` / `AI_MAX_RETRIES` | 60 / 2 | |
| `DJANGO_TIME_ZONE` / `DJANGO_LANGUAGE_CODE` | Asia/Shanghai / zh-hans | |

### 4.3 MySQL 5.6 兼容（本机现状）

- Django 4.2 官方不支持 5.6 → `DB_SKIP_VERSION_CHECK=True`；
- 5.6 无 `utf8mb4` 完整支持 → `DB_CHARSET=utf8`；
- 5.6 **无原生 JSON 字段** → 全项目的结构化小数据一律 `TextField` 存 JSON 字符串；
- 测试库字符集必须在 `settings` 的 `TEST` 段显式指定，否则继承 latin1，中文写入报 1366。

> 正式交付建议升到 MySQL 8.0，升完可删掉 `DB_CHARSET` / `DB_SKIP_VERSION_CHECK` 两行。

### 4.4 初始化

```bash
python manage.py migrate
python manage.py seed_users       # 演示账号（admin / teacher / student，密码 Exam@123456）
python manage.py seed_questions   # 20 知识点 + 19 道样题
python manage.py seed_papers      # 3 份演示卷
python manage.py seed_exams       # 3 场演示考试（--reset 重建）
python manage.py runserver
```

题库想扩到 700+ 道：`python manage.py ai_fill_bank`（会调大模型，**花钱**）。

## 5. 模块设计

### 5.1 模块一 用户与认证（`apps/users`）

- 自定义 `User`（`role` = admin/teacher/student）+ 自定义 Manager/QuerySet；
- 登录后端支持**用户名 / 邮箱 / 学号**（`backends.py`）；
- 页面 mixin 与 DRF 权限类都在 `apps/common/`：`IsAdmin` / `IsTeacher` / `StudentRequiredMixin` 等。

### 5.2 模块二A AI 适配层（`apps/ai`）

| 组件 | 职责 |
|---|---|
| `providers/` | 各厂商 HTTP 适配，统一 `chat()` 接口 |
| `prompts/*.txt` | 提示词模板，`{{变量}}` 字面量替换（**不用 `str.format`**，避免与 JSON 花括号冲突） |
| `schemas.py` | 把模型输出当**不可信输入**：能修就修、修不了丢进 `errors`；阈值分档 `score_by_threshold()` |
| `mocks.py` | 无 Key / 测试时的本地实现，**判定规则与各模块 constants 刻意一致** |
| `services.py` | `build_provider()` 统一入口 + 调用日志 `AIRequestLog` |

### 5.3 模块二B 题库与知识点（`apps/questions`）

- 六题型；`QuestionOption` 存选项与 `is_correct`；
- **软删除**（`is_active=False`）保护历史试卷可追溯；
- 知识点成树；删除时校验**整棵子树**——子树内还有在用题目则拒绝（12030），没有才连子节点一起物理删除；
- AI 出题返回**草稿**，`batch/` 才入库；导入导出走 openpyxl。

### 5.4 模块三 试卷与组卷（`apps/papers`）

- 三层：`Paper` → `PaperSection` → `PaperQuestion`；
- `PaperQuestion` 存**分值/题型/难度快照**，题库改题不影响历史卷；
- 冗余汇总（`total_score` / `question_count`）由 `PaperService.recalc()` 统一维护；
- **智能组卷由算法定题**（`PaperComposeService`，带 `seed` 可复现），
  LLM **只写组卷说明**——绝不让模型直接输出题目 id；
- **三种组卷方式**（共用同一套抽题算法，区别只在「蓝图从哪来」和「要不要调模型」）：

  | 方式 | 蓝图来源 | 是否调 AI | 入口 |
  |---|---|---|---|
  | 手动 | 教师逐题挑 | 否 | 工作台「从题库加题」 |
  | AI 智能组卷 | 教师配蓝图（题型/题数/分值） | **是**（只写组卷说明） | `papers/ai-compose/` |
  | 随机组卷 | **按题库库存自动生成**（`auto_blueprint()`） | **否** | `papers/random-compose/` |

- 随机组卷的蓝图规则：按所选知识点范围内的**库存占比**分配题型题量（最大余数法），
  只给有库存的题型分配；请求量超过库存时**封顶到库存**（有多少抽多少，不报「不足」）。
  蓝图生成是确定性的，随机只发生在 `compose()` 的抽题阶段（由 `seed` 控制），因此仍然可复现；
- `generation_mode` 区分 `manual` / `ai` / `random` / `hybrid`，便于统计各方式的产出。

### 5.5 模块四 在线考试（`apps/exam`）

- **服务端是唯一计时权威**：开考时算好 `deadline_at` 落库，前端只展示；心跳返回的剩余时间只作"时钟漂移"观测，**不参与判据**；
- 防答案泄漏只有一个出口：`_question_payload()` 只转白名单字段，学生序列化器里**根本没有**答案/解析/正确标记；
- 状态机：库里只存 draft/published/finished/archived，"进行中"由 `computed_status()` 按时间算（**返回值一律 `str()` 包装**）；
- 乱序种子 `shuffle_seed` 落在 attempt 上 → 刷新 / 换设备 / 断网重连题序一致；
- 行为计数聚合在 attempt 上，逐条明细留给模块八。

### 5.6 模块五 判分与成绩（`apps/grading`）

- 客观题 `ObjectiveGradingService` 是**纯函数**（不写库 / 不调 AI / 不依赖时间）；
- 多选策略 `strict` / `partial` / `penalty` 定义在 `apps/exam/constants.py`，
  作为 `Exam.multiple_choice_policy` 一列（属考试配置，非判分器私货）；
- 主观题 AI 评分 + 教师复核，复核写 `GradingFeedback` 审计表；
- 汇总只一个写入口 `GradingService.recalc()`，每次从 `Answer` **重算**；
- 成绩可见性：`graded` 必可见；`auto_graded` 仅当 `exam.show_score_immediately`。

### 5.7 模块六 学情分析（`apps/analytics`）

- **统计是只读模型，不建表**（唯一新表 `StudentAnalysisReport` 只缓存 AI 诊断文本，24h）；
- 掌握度**向上归并**到祖先知识点，同一题对"祖先 ∩ 自身"去重；
- 薄弱 = 正确率 <0.60 **且**样本 ≥2；样本不足标 `UNKNOWN`（不给结论）；
- 区分度 = 总分前 27% 与后 27% 在该题得分率之差，样本 <4 给 `None`；
- 趋势用**最小二乘线性回归**，≥3 个点才预测；
- AI 诊断：**数字由代码算，话由模型说**，GET 不调模型，`POST diagnosis/` 才调。

### 5.8 模块七 个性化推荐（`apps/recommend`）

- **不建表**：推荐是确定性函数 `md5(学生|日期|题目)`，当天不变、跨天轮换；
- 匹配度 = `(0.65×薄弱度 + 0.35×难度适配度) × (1 + 0.30×协同分)`；
  - 薄弱度 = `(1-正确率) × 证据充分度`（正确率 0% 是饱和的，折进样本量才有区分度）
  - 难度适配 = `max(0, 1 - |d - target|/3)`，**不是越难越好**
  - 协同过滤是**乘数加成**，冷启动自动退化为纯内容推荐
- 同知识点限流 ≤2 题；AI 只改理由、不改选题。

### 5.9 模块八 作弊行为检测（`apps/proctoring`）

- 只新增一张 `ExamBehaviorLog`（逐条埋点），与 `ExamAttempt` 的聚合计数是**两个粒度**；
- 埋点入口复用 `ExamAttemptService.report_behavior()`：**惰性 import + 保存点 + 吞异常**，
  埋点失败不阻断考试链路；
- 表里**只存事实、不存结论**，结论由规则引擎**读时现算** → 改阈值后历史结论不过时；
- 9 条规则 + 风险分档集中在 `constants.py`，页面/接口/测试/冒烟读同一份；
- 孤立森林：`ANOMALY_MIN_SAMPLES=8` 以下不训练；`random_state=42` 保证名单可复现；
  未装 sklearn 时降级稳健 z-score（`method` 如实告知）。

## 6. 关键设计决策（不能绕开）

> 完整编号版（60 条）见 `.workbuddy/memory/MEMORY.md`，这里按主题精选。

**分层与一致性**
1. 派生汇总值**只有一个写入口**且每次重算（`recalc()`），不做 `+=`。
2. 历史数据用**快照**（卷内题目存分值/题型/难度）与**软删除**（题库）保护。
3. 跨模块只读：模块七/八读模块五/六/四的结果，**绝不反向改写**。

**安全**
4. 答案防泄漏靠**序列化器分层**，不靠前端隐藏。
5. 跨人访问返回 **404 而非 403**（不当 id 探测器）。
6. 学生侧所有接口与页面默认不可见答案 / 解析 / 正确标记。

**确定性（可复现）**
7. 所有随机都由**种子**决定：组卷 `seed`、乱序 `shuffle_seed`、推荐 `md5(学生|日期|题目)`、
   孤立森林 `random_state=42`。

**AI 纪律**
8. **算法定正确性，LLM 只负责可解释性**（组卷、推荐选题、学情数字都不交给模型）。
9. **降级不抛异常**：模型不可用 / 返回脏数据 → 退化为本地策略 + `degraded=True`。
10. **AI 是花钱动作**：默认不开（判分不带 `with_ai` 只判客观题；GET 推荐与诊断不调模型），
    只有显式 POST 才调，且带 TTL 缓存。
11. 提示词末尾的指令必须写成独立 `【小节】`，否则 mock 解析会把指令当数据行。

**统计口径**
12. **样本不足不给结论**（薄弱 ≥2、趋势 ≥3、区分度 ≥4、异常检测 ≥8）。
13. 分母为 0 返回 `None` 而非 0（0 会被误读成"全军覆没"）。
14. 阈值 / 权重 / 规则目录**集中在各模块 `constants.py`**，一处定义多处读取。

**前端与数据**
15. MySQL 5.6 无 JSON 字段 → 结构化小数据一律 `TextField` 存 JSON 字符串。
16. 导出参数**不能叫 `format`**（DRF 用它做内容协商会撞名 404），本项目用 `file_format`。
17. CSV 一律带 **UTF-8 BOM**，否则 Excel 打开中文乱码。
18. 时间显示必须 `timezone.localtime()` 转本地时区。

## 7. AI 接入设计

```
业务代码 → build_provider(scene) → apps/ai/providers/<厂商>.py → HTTP
                    │
                    ├─ 渲染 prompts/<scene>.txt（{{变量}} 字面量替换）
                    ├─ 调 chat()
                    ├─ schemas.py 解析与校验（脏数据能修就修，修不了进 errors）
                    └─ 写 AIRequestLog（provider/model/scene/token/耗时/是否 mock）
```

| 场景 | 提示词文件 | 说明 |
|---|---|---|
| 智能出题 | `generate_questions.txt` | 教材文本或知识点 → 题目草稿 |
| 题目解析 | `explain_question.txt` | 生成 / 重写解析 |
| 主观题评分 | `grade_subjective.txt` | 语义相似度 + 给分理由 |
| 学情诊断 | `analyze_weakness.txt` | 输入代码算好的正确率表，只让模型说话 |
| 组卷说明 | `compose_notes.txt` | 抽题由算法做，模型只写说明 |
| 推荐理由 | `recommend_practice.txt` | 只改写措辞，**不改选题** |

**降级链**：无 Key / 超时 / 返回非 JSON / 抛异常 → `mocks.py` 的对应实现 → 标记
`is_mock=True` 或 `degraded=True`，功能不中断。

**测试强制 mock**：`settings/base.py` 在 `"test" in sys.argv` 时清空所有 provider 的 api_key
→ 单测不依赖外网、不花钱、可复现。

## 8. 前端约定

- Django 模板 + Bootstrap 5，**无构建步骤**；
- AJAX 统一走 `static/js/api.js` 封装（自动带 JWT、统一解 `code/message/data`、统一 toast）；
- 图表用 **ECharts**（CDN），服务端把数据拼成 `{indicator,values}` / `{buckets,stats,normal}`
  / `{points,fit}` 等结构直接塞给前端，前端不做数据加工；
- 页面通过 `views_pages.py` 注入 `active_menu` 控制导航高亮；
- 角色拦截用 `apps/common/mixins.py` 的 mixin（教师页学生访问 → 403）。

新增页面后务必跑 `python scripts/check_inline_js.py`（渲染后把内联 `<script>` 交给
`node --check`，查的是浏览器真正执行的代码）。

  `RecommendBaseTest` → `ProctoringBaseTest`，**优先继承最贴近的那个**；
- 跑测试自动放宽限流、`setUp` 清缓存（否则用例互相污染）；
- 冒烟脚本**会真实写数据**，结尾清理；模块四那场验收考试因有作答只能归档，会留 1 场
  `[验收]` 开头的考试（这是设计，不是垃圾数据）。

## 10. 部署（生产）

```bash
# 1. 依赖与环境
pip install -r requirements.txt gunicorn
cp .env.example .env      # 填 DJANGO_SECRET_KEY / DJANGO_DEBUG=False / DB_* / *_API_KEY

# 2. 数据库（推荐 MySQL 8.0）
python manage.py migrate

# 3. 静态文件（DEBUG=False 后必须做，否则样式全丢）
python manage.py collectstatic --noinput

# 4. 起服务
gunicorn OnlineExam.wsgi:application -b 127.0.0.1:8000 -w 4
```

要点：
- `DEBUG=False` 时 `ALLOWED_HOSTS` 必须显式配置；
- Nginx 转发 `/static/` 与 `/media/` 到本地目录，其余反代给 gunicorn；
- 生产 settings 在 `OnlineExam/settings/production.py`（`DJANGO_SETTINGS_MODULE` 指过去）；
- 定期跑 `python manage.py purge_behavior_logs --days 180` 裁剪埋点（先 `--dry-run` 预览）。
