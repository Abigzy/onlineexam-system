# 接口文档

> **数据源**：由 `drf-spectacular` 从代码生成（`python manage.py spectacular`），
> 与实现**同源**——改了代码重新生成即可，不存在"文档与代码不一致"。
> 在线可调试版本：`http://127.0.0.1:8000/api/docs/`（Swagger UI）。

- Base URL：`http://127.0.0.1:8000`
- API 前缀：`/api/v1/`（健康检查 `/api/health/` 除外）
- 共 **124 个接口操作**（按「路径 × 方法」计：GET 61 / POST 42 / PUT 7 / PATCH 7 / DELETE 7），覆盖 12 个分组。**不含** DRF 自动生成的 `api/v1/` 根路由（那是调试用的路由索引，不是业务接口）
- 内容类型：`application/json`（文件上传用 `multipart/form-data`）

## 1. 通用约定

### 1.1 鉴权

JWT（SimpleJWT）。除注册 / 登录 / refresh / 健康检查外，其余接口都要带：

```http
Authorization: Bearer <access_token>
```

| 令牌 | 有效期 |
|---|---|
| access | 2 小时 |
| refresh | 7 天，且 `ROTATE_REFRESH_TOKENS=True`（刷新会换新 refresh） |

登录支持**用户名 / 邮箱 / 学号**三种账号（自定义 `AuthBackend`）。

### 1.2 统一响应体

所有接口（含报错）都是这个信封：

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

### 1.3 错误码与 HTTP 状态

| 段 | 含义 |
|---|---|
| `0` | 成功 |
| `4xxxx` | HTTP 状态码 × 100（400 → `40000`，401 → `40100`，403 → `40300`，404 → `40400`） |
| `5xxxx` | 服务端错误 |
| `1xxxx` | 业务语义错误（如 `10001` 用户名已存在、`13002` 只有草稿可改），默认 `10400` |

**成功判定是 `code == 0`；但断言必须同时看 HTTP 状态码。**
HTTP 状态码与该错误的语义一致（认证 401、越权 403、资源不存在 404、参数错误 400、上游异常 502），
业务码另给细分原因——两者是**并行信息**，不是"业务错误一律 200"。

实测对照（2026-11-02，演示库真实返回，非推断）：

| 场景 | HTTP | code |
|---|---|---|
| 匿名访问需登录接口 | 401 | `40100` |
| 登录：账号不存在 / 密码错误 | 401 | `40100` |
| 登录：账号已停用 | 401 | `40101` |
| 班外学生开考（不在参考范围） | 403 | `10431` |
| 非本人提交答案 / 交卷 | 403 | `10431` |
| 无权管理该班级 | 403 | `14003` |
| 访问不存在的资源 / 跨人访问 | 404 | `40400` |
| 参数校验失败 | 400 | `40000` |
| 业务规则拒绝（已发布卷改卷头等） | 400 | `13002` / 各模块自定 |
| AI 上游异常 | 502 | `11001` |

> 两个容易误判的点：
> * `10431` 是「不在参考范围」的专用码，比通用 `40300` 更精确，**不能只断言 403**；
> * `14003` 只用于「对象存在但当前用户无权」的入口（如班级成员），
>   其余跨人访问一律 `404 / 40400`——不拿 403 当「这个 id 存不存在」的探针。

### 1.4 分页（**有两种形态，用例要两套模板**）

**形态 A：DRF 标准分页**（users / questions / papers / exams / attempts 等）

`?page=2&page_size=50`（`page_size` 最大 100，部分列表用 `LargePagination`，默认 50 / 最大 500）。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "count": 128, "total_pages": 13, "page": 1, "page_size": 10,
    "next": "http://.../api/v1/questions/?page=2", "previous": null,
    "results": [ ]
  }
}
```

**形态 B：手写全量返回**（classrooms / grading / analytics / proctoring 等）

只有 `{count, results}`，**没有 `page` / `total_pages` / `next`**，一次性返回全部，
**传 `?page=` 不生效**（不会报错，但也不会分页）——断言分页字段存在会直接失败。

```json
{"code": 0, "message": "success", "data": {"count": 9, "results": [ ]}}
```

> 判断方法：看响应里有没有 `total_pages`。有 → 形态 A，可断言翻页；
> 没有 → 形态 B，只能断言 `count` 与 `len(results)` 一致，**不要**去翻页。

**分页参数的两条边界**（实测口径，别按 DRF 默认去猜）：

| 请求 | 返回 | 说明 |
|---|---|---|
| `?page=0` / `?page=-1` / `?page=abc` | **400 / `40000`** | 参数错误。DRF 默认给 404，本项目**改成了 400**——路径错和参数错要能分开 |
| `?page=99999`（格式对、超出总页数） | **404 / `40400`** | 这一页确实不存在 |
| `?page_size=1000`（超过上限） | 200，**静默截断到上限** | 上限 100（`LargePagination` 是 500） |

> `page_size` 被截断时**不是完全静默**：响应里的 `page_size` 字段返回的是**实际生效值**，
> 前端拿它和请求值一比就知道被压过了。若需要强提示，只能自己加响应头或字段。

### 1.5 限流

| Scope | 速率 | 适用 |
|---|---|---|
| `auth` | 30/min | 登录 / 注册等 |
| `ai` | 20/min | 所有会调大模型的接口 |

> 跑单元测试时自动放宽到 10000/min（`settings/base.py` 判 `"test" in sys.argv`）。

### 1.6 其他

- 时间格式：`YYYY-MM-DD HH:MM:SS`（服务端本地时区）
- 筛选：django-filter + `?search=` + `?ordering=-created_at`
- **跨人访问返回 404 而非 403**（不让学生拿状态码探测 id 是否存在）
- 列表接口一律返回 `{count, results}` 信封，**不返回裸数组**；是否真分页见 §1.4
  （classrooms / grading / analytics / proctoring 是手写全量返回，没有翻页字段）

### 1.7 自动化测试前置条件

跑接口自动化前必须确认这三件事，否则会出现「时稳时不稳」的假故障：

1. **限流**：`auth` 30/min、`ai` 20/min（见 §1.5）。批量跑登录 / 注册用例很容易在第 31 个
   请求上拿到 429，被误判成功能缺陷。`manage.py test` 里判 `"test" in sys.argv` 会自动放宽到
   10000/min，但**打真实服务（runserver）跑脚本时不会放宽**，要么调高配置，要么错开调用节奏。
2. **计时以服务端为准**：`deadline_at` 在开考时算好落库，客户端时间不参与判据；交卷有
   `SUBMIT_GRACE_SECONDS=30` 宽限。所以「超时自动交卷」类用例不要靠 sleep 卡点——
   直接把 `deadline_at` 改到过去，否则跑一次要等满考试时长。
3. **AI 会真实联网**：`.env` 里 `AI_PROVIDER=deepseek` 且 Key 有值时，`with_ai=true` 的接口
   会真的调用外部模型——慢、花钱、结果不可复现。自动化用例必须显式 mock
   （`manage.py test` 时会自动降级 mock），走真实服务时要么不传 `with_ai`，
   要么把 provider 切成 mock。

> **成绩可见性（唯一口径：`ExamAttempt.score_visible()`）**
>
> | 作答状态 | 可见性 | 说明 |
> |---|---|---|
> | `graded` | **可见** | 教师已出分，「出分」这个动作本身就是发布成绩 |
> | `auto_graded` | 看开关 | 仅当 `exam.show_score_immediately = true` |
> | 其余（`in_progress` / `submitted` / `reviewing` / `timeout`） | **不可见** | |
>
> 不可见时，学生侧所有接口的**得分与逐题对错一律 `null`**——`attempts/`、
> `attempts/{id}/`、`exams/` 里嵌套的 `my_attempt`、`attempts/{id}/paper/`、
> `attempts/{id}/answers/`，以及 `grading/attempts/{id}/report/` 的顶层
> `score` / `passed` / `counts.correct` / `counts.wrong`。
> 只给一个 `show_score: false` 的开关是不够的：字段照常带宽的话，前端一个疏忽、
> 或者直接调接口，分数就到手了。本项目对「答案」的做法是字段根本不给，分数同理。
>
> 规则只住在 `apps/exam/models.py`，评分侧 `ScoreReportService.score_visible()` 是**委托**。
> （曾经两处各写一份，`graded` 上结论相反：`/report/` 说可见、`/answers/` 给 `null`。）
>
> 两个**不属于**得分、照常下发的 `score`：卷面 `paper.sections[].questions[].score`
> 是**每题满分**（答题页要显示分值），`attempt.total_score` 是整卷满分。

> **「面向全体」的参与范围（按创建者收窄）**：`open_to_all=true` 时，范围由 `Exam.open_to_all_scope()` 决定——
> 教师创建的考试只对该教师**可管理班级**（自己创建 / 任班主任 / 在授课名单里）的学生开放；
> 管理员创建或无创建人时才是全校在册学生。
> 影响：班外学生 `GET /api/v1/exams/` **看不到**该考试，`POST /api/v1/exams/{id}/start/` 返回
> **404 / `40400`**——`start` 走的是学生 queryset，班外学生连考试都取不到，在 `get_object()`
> 就 404 了，**不会**走到 service 里那条 `403 / 10431`（那条只对「能取到考试但不在范围」的
> 场景有效，属防御性保留）。这与「跨人访问一律 404」的纪律一致，不拿 403 当 id 探针。
> `overview` / `participant_count` 的应考人数也按该范围计算。

## 3. 关键接口详解

### 3.1 登录

```http
POST /api/v1/auth/login/
{"username": "student", "password": "Exam@123456"}
```

```json
{
  "code": 0, "message": "success",
  "data": {"access": "eyJhbGci...", "refresh": "eyJhbGci...", "user": {"id": 3, "username": "student", "role": "student"}}
}
```

### 3.2 学生答题主流程

```
POST /api/v1/exams/{id}/start/        → 拿 attempt_id 与卷面（不含答案）
GET  /api/v1/attempts/{id}/paper/     → 断网重连恢复卷面（题序一致）
POST /api/v1/attempts/{id}/save/      → 单题暂存（边答边存）
POST /api/v1/attempts/{id}/heartbeat/ → 心跳，返回服务端权威剩余秒数
POST /api/v1/attempts/{id}/behavior/  → 上报切屏/粘贴/退出全屏
POST /api/v1/attempts/{id}/submit/    → 交卷
GET  /api/v1/attempts/{id}/result/    → 看结果（受成绩可见性约束）
```

**行为上报体**（会被模块八落逐条埋点）：

```json
{"events": [{"type": "switch", "count": 1, "duration_seconds": 12, "question_id": 101}]}
```

`type` 取值沿用 `apps/exam/constants.BehaviorEvent`：`switch` / `paste` / `fullscreen_exit` / `blur` / `heartbeat`。

### 3.3 判分

```http
POST /api/v1/grading/attempts/{id}/grade/
{"with_ai": true}          # 不带 with_ai 时只判客观题
```

要点：
- 客观题是**纯函数判分**，不调 AI、不写库之外的东西；
- AI 只参与主观题（简答 / 论述），按阈值 ≥0.7 满分、0.4~0.7 线性插值、<0.4 不得分；
- 单题失败不打断整批，退化为「【待人工判分】」；
- **总分只有一个写入口**（`GradingService.recalc()`），每次从 `Answer` 重算，幂等。

### 3.4 每日练习推荐

```http
GET /api/v1/recommend/students/3/practice/?subject=&size=6&offset=0
```

返回 `items[]`，每条含：`question`（题目）、`match_score`（匹配度）、`reason`（一句话理由）、
`knowledge_point`、`answered_before`（是否做错过）、`ai`（GET 时恒为 `null`）。
`summary` 给出候选数、返回数、平均匹配度、目标难度、协同过滤是否可用。

> **GET 绝不调大模型**；`POST` 同一地址才让模型改写理由（选题与顺序不变）。

### 3.5 作弊检测报告

```http
GET /api/v1/proctoring/exams/{id}/report/?only_suspicious=true&top_n=20
```

返回 `overview`（作答数 / 事件总数 / 可疑人数 / 平均分）、`rows[]`（每位考生：风险分、
档位、命中规则、各项计数、异常分）、`anomaly`（是否够样本、`method`）、`thresholds`。
`top_n=abc` 这类非法参数返回 **400**，不 500。
